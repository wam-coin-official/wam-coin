2,000,000 WAM is minted in the genesis block. Not one coin of it can move

```
2027-09-15   2028-09-15   2029-09-15   2030-09-15   2031-09-15
```

The scripts are bare, not P2SH - the unlock date is in the output itself,
not behind a hash you would have to trust us about. Read it out of block 0:

```
wam-cli getblock $(wam-cli getblockhash 0) 2
```

*2. The releases are signed, and one command checks it.*

```
4BD4 A8D3 AFD4 3F5C BCB5  00E2 3798 462F E00A DBA4
```

https://github.com/wam-coin-official/wam-coin/releases/tag/v0.1.6

Download the release, SHA256SUMS and SHA256SUMS.asc into one directory.
The checker and the key come from the repository, deliberately a different
place from the binary:

```
git clone https://github.com/wam-coin-official/wam-coin
bash wam-coin/scripts/verify_release.sh ~/Downloads
```

It refuses to say ok unless the signature is good, made by that exact
fingerprint, and covering the file in front of you. Check the fingerprint
over HTTPS here, not against this message - a message is exactly the thing
an attacker gets to write:

https://github.com/wam-coin-official/wam-coin/blob/main/SECURITY.md
